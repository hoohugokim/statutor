# Runbook: v0.4.0 real-home dogfood

## Authority and stop conditions

This is a reviewed runbook, not authorization to mutate the maintainer's home.
Run each mutation only after separate approval naming that phase. Use the
v0.4.0 candidate checkout directly so an older installed `statutor` cannot
silently substitute different behavior:

    PYTHONPATH=core python3 core/statutor_core.py global ...

Stop on any unplanned target, missing backup, `conflict` other than the two
known unmanaged instruction files, managed-target drift, or new diagnostic.
Never use `--force`, edit a receipt, edit the foreign skill lock, or repair an
unrelated skill during this run.

## Phase 1 — initialize canonical state

First mutation, separately approve:

    PYTHONPATH=core python3 core/statutor_core.py global init --json

This creates only `~/.config/statutor/` canonical scaffolds and
`~/.local/state/statutor/` state. It must not change any host instruction or
skill target. Review the emitted roots and then edit the canonical common file
and host overlays as ordinary human-owned sources.

Re-run the read-only plan:

    PYTHONPATH=core python3 core/statutor_core.py global plan --json

Expected: Claude and Codex remain unmanaged conflicts; OpenCode is a create
with an explicit fallback warning.

## Phase 2 — adopt instructions one host at a time

Each adoption pre-displays its plan, backs up the exact original, copies the
original bytes into that host's canonical overlay, and installs a generated
projection. Approve and verify Claude before proceeding to Codex:

    PYTHONPATH=core python3 core/statutor_core.py global adopt claude --json
    PYTHONPATH=core python3 core/statutor_core.py global status --host claude --json
    PYTHONPATH=core python3 core/statutor_core.py global adopt codex --json
    PYTHONPATH=core python3 core/statutor_core.py global status --host codex --json

Confirm that each original body occurs byte-for-byte in its projection and
that the receipt names an initial backup. Do not create OpenCode's native file
until explicitly accepting the precedence change:

    PYTHONPATH=core python3 core/statutor_core.py global apply --host opencode --json
    PYTHONPATH=core python3 core/statutor_core.py global status --host opencode --json

## Phase 3 — dogfood one new skill

The repository's `skills/statutor` name is absent from the current real-home
inventory, making it a bounded new-only candidate. Import copies it into the
human-owned canonical root; apply creates only the portable and Claude trees:

    PYTHONPATH=core python3 core/statutor_core.py global skill import ./skills/statutor --json
    PYTHONPATH=core python3 core/statutor_core.py global skill plan --json
    PYTHONPATH=core python3 core/statutor_core.py global skill apply --json
    PYTHONPATH=core python3 core/statutor_core.py global status --json
    PYTHONPATH=core python3 core/statutor_core.py global doctor --json

Acceptance: the new skill projections are identical and Statutor-owned;
foreign-locked names are unchanged; no pre-existing invalid/extra entry was
rewritten; no new error appears. The known baseline skill diagnostics may keep
doctor nonzero and must be compared by code/path rather than suppressed.

## Rollback

Rollback in reverse order. Every command refuses modified managed targets:

    PYTHONPATH=core python3 core/statutor_core.py global skill uninstall --json
    PYTHONPATH=core python3 core/statutor_core.py global uninstall --host opencode --json
    PYTHONPATH=core python3 core/statutor_core.py global uninstall --host codex --json
    PYTHONPATH=core python3 core/statutor_core.py global uninstall --host claude --json

Expected: the new skill targets and OpenCode file return to absence; Claude and
Codex regain their exact original bytes. Canonical sources, receipts, journals,
and backups remain as audit evidence; deleting that evidence is outside this
runbook.
