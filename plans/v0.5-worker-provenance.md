# v0.5 worker provenance

## Goal

Answer "which harness worked here last?" with an explicit evidence basis while
also preserving a portable shift-change answer and collision safeguard across
machines. Do not turn weak hook signals, filesystem timestamps, or model
guesses into provenance, and do not require a live coordinator.

## Vocabulary

- `activity`: a harness session reached a proved Statutor integration point.
- `attempt`: a pre-execution event requested a potentially mutating tool.
- `mutation`: a host surface proved a tracked-worktree mutation succeeded.
- `completed`: the executor left a valid HANDOFF and recorded its attribution.
- `active`: a non-expired local session lease; never proof of useful work.

The default query basis is `completed`. Each result carries its basis and
timestamp. Unknown evidence returns `unknown`, not a fallback guess.

Stable harness IDs are `claude`, `codex`, `opencode`, `custom`, `human`, and
`unknown`. Optional `role` (`primary`, `subagent`, `unknown`) and
`origin_harness` distinguish the executing harness from its invoker when the
host exposes that fact. Every record also carries the random Statutor
`machine_id` and optional label snapshot. User-facing aliases are presentation
only.

## Machine identity

On first provenance use, create:

```text
$XDG_STATE_HOME/statutor/machine.json
```

Fall back to `$HOME/.local/state`; use mode 0600 and atomic replacement. Schema
v1 contains a random opaque `machine_id`, creation time, and optional
human-supplied label. The ID is installation-scoped: never derive it from a
hostname, login, IP/MAC address, hardware serial, OS machine identifier,
repository, or path. A label is display metadata, not identity.

Restoring or cloning the state directory deliberately preserves identity. When
the copy becomes a separate machine, `statutor machine rotate` creates a new ID
after explicit confirmation; old records retain their original ID and label
snapshot. Rotation never rewrites committed HANDOFF history.

## Portable completion record

New HANDOFF scaffolds add this adjacent to `last_verified`:

```yaml
last_worker: unknown
last_machine: unknown
handoff_id: none
supersedes: none
```

An executor changes them to the stable harness and opaque machine IDs when
rewriting and verifying the handoff. An optional `last_machine_label:` is a
human-readable snapshot and may be omitted to avoid publishing a label.
Existing HANDOFF files without these fields remain valid in v0.5; doctor
reports an actionable diagnostic rather than a floor error. A successful
completion-recording command validates the final HANDOFF before updating local
state. Hooks never silently rewrite this executor-owned file.

Each completed rewrite replaces `handoff_id` with a fresh random opaque ID and
sets `supersedes` to the prior ID. A reconciliation may supersede multiple
comma-separated IDs. If machines A and B both start from `h0`, their independent
`hA -> h0` and `hB -> h0` records are siblings rather than a last-write-wins
sequence. A reconciled `hC` names both `hA, hB` after a human or executor has
resolved the substantive handoff state.

## Local registry

Default root:

```text
$XDG_STATE_HOME/statutor/projects/<project-id>/workers.json
```

Fall back to `$HOME/.local/state`. Derive `project-id` from the resolved Git
common directory when available, otherwise the marked ledger root; retain a
separate worktree identity so queries can aggregate a repository or select the
current worktree. Paths and roots must be injectable for hermetic tests.

Schema v1 stores, at minimum:

- repository/worktree identity and schema version;
- latest activity, attempt, confirmed mutation, and completed records;
- per-harness latest records and bounded active-session leases;
- harness, role, origin harness, machine ID/label snapshot, timestamp, opaque
  session ID, scope, and evidence;
- session-start HEAD, worktree, HANDOFF digest, and `handoff_id` baselines used
  only for collision comparison and completion compare-and-swap;
- capability metadata explaining which facts each adapter can prove.

Use a lock plus same-directory atomic replacement. Keep no prompts, tool
arguments/results, diffs, filenames touched, model names, or transcript text.
Session IDs are opaque and may be hashed before persistence.

## CLI contract

```console
statutor machine show [--json]
statutor machine set-label LABEL
statutor machine rotate
statutor worker begin --harness HOST
statutor worker show [--basis completed|mutation|activity|attempt] [--worktree] [--json]
statutor worker active [--worktree] [--json]
statutor worker record --harness HOST --event EVENT [metadata]
statutor worker complete [--session ID]
statutor worker compare REF [--json]
```

`machine show`, `worker show`, and `active` are read-only and return stable
JSON. Every worker result says `scope: machine-local` or
`scope: portable-handoff`. `record` is the narrow adapter/custom-harness
ingress: it requires an explicitly marked ledger, validates enums and
timestamps locally, and never accepts conversation content. Completion
recording additionally requires a valid HANDOFF attributed to the current
machine ID, a fresh `handoff_id`, and `supersedes` matching the recorded
baseline. If another local session completed first, compare-and-swap fails with
both actors identified rather than silently replacing its state.

`worker compare REF` is read-only and entirely offline: the caller first makes
any desired Git ref available locally. It reads HANDOFF from the merge base,
current revision, and `REF`; reports base/ours/theirs IDs and worker/machine
attribution; classifies unchanged, successor, stale, or sibling histories; and
lists the IDs a reconciliation HANDOFF must supersede. It never invokes network
or mutating Git commands and never chooses or writes merged HANDOFF content.

Optional `Statutor-Harness:` and `Statutor-Session:` Git trailers are historical
evidence only. v0.5 does not inject trailers, rewrite commits, or use authorship
as the current worker.

## Adapter rule

Each adapter declares capabilities and records only proved events. In
particular, PreToolUse/tool-before records `attempt`, never `mutation`. Where a
host lacks a post-success or session-role signal, the corresponding field stays
unknown and status explains the limitation. A manual/custom integration can use
`worker record`; automatic adapters remain silent outside `.statutor.yaml` per
D-0019.

## Active leases

A session start may create a short lease renewed only at integration points.
Expiry is conservative and visible; it does not assert termination. Concurrent
sessions are all reported, including branch/worktree when available. The
registry warns about possible overlap but never locks a repository or blocks a
harness in v0.5. Leases describe only the current machine; v0.5 does not claim
that another machine is idle.

## Collision behavior

Same-machine sessions get an early warning from overlapping leases and a hard
completion CAS against their captured HANDOFF baseline. Cross-machine sessions
remain unknowable while disconnected. Once both commits or refs are local,
their distinct `handoff_id` and machine lines make ordinary Git merging
conservative, while `worker compare REF` explains the collision. Resolution is
a fresh verified HANDOFF that supersedes every sibling ID; Statutor validates
the lineage but leaves all substantive reconciliation to the executor.

## Acceptance

- Old ledgers and v0.4 global state remain valid without migration.
- Default output identifies the last verified completed harness and machine or
  `unknown`, including whether evidence is local or HANDOFF-portable.
- Activity, attempt, mutation, completion, and active leases never collapse.
- Atomic concurrent writers cannot corrupt or silently lose newer state.
- Linked worktrees aggregate at repository scope and separate with `--worktree`.
- Two fake machines using one Git history retain distinct random IDs; a pulled
  HANDOFF identifies the remote completing machine without importing its local
  activity or leases.
- Two machines completing from one HANDOFF form detectable siblings; comparison
  names both actors and required supersedes, and only a fresh reconciliation
  record restores a linear current state.
- Cloned state preserves identity until an explicit rotation; rotation leaves
  old records and committed history attributable to the prior ID.
- Crashed sessions age out without being labeled completed.
- Fake HOME/XDG roots and nested ledger roots are covered end to end.
- Claude, Codex, and OpenCode tests pin current releases and expected capability
  gaps; unsupported host facts remain explicit.
- Registry inspection proves that no conversation content is persisted.

## Non-goals

Remote synchronization/presence, distributed locking, user authentication,
hardware fingerprinting, surveillance of unintegrated processes, prompt
auditing, automatic commit attribution, fetching or mutating Git refs,
automatic HANDOFF merging, blocking concurrent agents, and inferring identities
from prose or model names.
