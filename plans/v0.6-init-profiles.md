# v0.6 init profiles

Task: T-0043. Decided: no mandatory layout (candidate D-0024); profiles
scaffold conventional directories only, never enforce.

## Goal

`statutor init` grows from one fixed skeleton to type-aware scaffolding
that is initiated by default and trivially opted out of — per run and per
user — while the trust floor, doctor, policy schema, and Rust twin stay
exactly as they are.

## Profiles (directories only, never files-with-content, never policy)

| Profile | Adds over `min` | Detected by |
|---|---|---|
| `min` | (today's behavior: ledger files, `plans/archive/`, `notes/`, CLAUDE bridge) | fallback |
| `none` | nothing beyond governed files (no extra dirs) | explicit only |
| `python` | `tests/` | `pyproject.toml`, `setup.py`, `setup.cfg` |
| `rust` | `tests/` | `Cargo.toml` |
| `node` | `test/` | `package.json` |
| `docs` | `docs/` | `mkdocs.yml`, `_quarto.yml`, existing `docs/` |

All creates are additive and idempotent: present paths (files or dirs) are
skipped, never overwritten or adopted — the same rule `run_init` already
applies to files. Profiles MUST NOT write policy, constitution content, or
ecosystem files (`src/` layouts, configs, gitignores): those are taste and
belong to the project, not the scaffolder.

## Opt-out precedence (highest first)

1. `statutor init --type <name>|none`
2. `STATUTOR_INIT_TYPE` env var
3. auto-detect (default): first marker hit wins in the order
   python > rust > node > docs, else `min`

Rationale: flag for one-offs, env for per-user preference (dotfiles set
once), auto-detect so the default run does something sensible. A future
`global.json` default is explicitly out of scope — env covers it.

## Hard guarantees (the D-0024 core)

- Scaffold-only: no new policy kinds, no floor/doctor changes, no Rust
  work (`init` is Python-only; the twin covers staged mode only).
- Definitions embedded in the kernel next to TEMPLATES (D-0003: no
  `profiles/` directory may ever exist, same as `templates/`).
- `min` output is byte-identical to today's `init` (existing tests must
  pass unmodified).

## Acceptance

- Matrix test per profile in empty tmp dirs: exact expected tree.
- Conflict matrix: multi-marker repos resolve per documented order.
- Opt-out matrix: `--type none`, env override, env-overridden-by-flag.
- Idempotence: second run is all-skips; pre-existing files/dirs untouched.
- Full gate green with zero changes to policy/floor/doctor/Rust code.

## Open questions

- Is per-type dir creation worth it versus a single richer `min`
  (the value is modest; most projects already have these dirs)?
- Should `docs` also scaffold anything else, or is an empty `docs/`
  sufficient signal?
- Defer: `global.json` init default, per-team shared profile presets.

## Alternatives considered

- Mandatory layout: rejected (fights ecosystems; needs policy-schema +
  Rust conformance for unproven value).
- Full content templates per type: rejected (presumes taste; violates the
  minimal-constitution rule).
- Doctor warnings for missing dirs: deferred (warning fatigue; revisit on
  real confusion).
